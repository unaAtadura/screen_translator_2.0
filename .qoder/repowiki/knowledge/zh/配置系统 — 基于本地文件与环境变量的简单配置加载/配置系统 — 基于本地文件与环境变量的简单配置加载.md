本仓库未实现统一的配置框架，而是采用“硬编码常量 + 本地密钥文件”的极简方式管理运行时配置。核心模式如下：

1. **启动器配置（boot.py）**
   - 所有与运行环境相关的参数以模块级常量定义在 `boot.py` 顶部：`REQUIREMENTS_FILE="requirements.txt"`、`VENV_DIR="venv"`、`LOG_FILE="boot.log"`、`PIP_RETRIES=3`、`MAX_LOG_SIZE_BYTES=500*1024` 等。
   - 这些常量直接决定虚拟环境路径、依赖清单文件名、日志轮转阈值等，修改需改动源码后重新打包/分发。

2. **API 密钥加载**
   - 主程序 `screen_translator_with_qwen.py` 通过 `read_api_key()` 从工作目录下的明文文件 `key.txt` 读取通义千问 API Key；若文件不存在则返回空字符串，导致 AI 客户端不初始化。
   - `.gitignore` 显式排除 `key.txt` 和 `glm-key.txt`，说明密钥由用户手动放置在工作目录。
   - 测试脚本中也有相同的 `read_api_key()` 复制实现，表明该模式被多处重复。

3. **AI 服务地址与模型名**
   - OpenAI 兼容接口的 `base_url="https://dashscope.aliyuncs.com/compatible-mode/v1"` 以及后续调用中的 `model_name` 均硬编码在主程序中，无外部配置文件支持。

4. **缺失的能力**
   - 没有使用任何配置格式文件（`.yaml` / `.toml` / `.json` / `.ini`）。
   - 没有环境变量注入机制（未见 `os.environ` / `getenv` 的使用）。
   - 没有配置校验、默认值合并、热重载或类型检查逻辑。
   - 没有集中化的配置对象或单例，各模块各自硬编码自己的常量。

**开发者应遵循的规则**
- 新增可配置项时，优先改为从 `key.txt` 所在目录的独立配置文件（如 `config.json`）读取，避免继续硬编码。
- 敏感信息（API Key、Token）只允许放在 `.gitignore` 已忽略的文件中，禁止写入源码或提交到版本库。
- 如需区分开发/生产环境，建议引入环境变量前缀（如 `SCREEN_TRANSLATOR_*`），并在启动入口统一解析，再注入到业务模块。
- 对现有硬编码常量（`COSYVOICE_WAV_FILE`、`base_url`、`PIP_RETRIES` 等）进行迁移时，保持向后兼容：当外部配置缺失时回退到当前默认值。
